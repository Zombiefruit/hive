Revised Architecture — Stream-JSON Skill Proxy

MCP access is mandatory. Headless (-p) mode doesn't have it. Stream-JSON does.

How It Works

Task Lifecycle: VEC-24 Implementation
── Stage: Inbox ──────────────────────────────
Triage agent detects VEC-24 from Linear + Slack DM
→ Detects repo: monolith-django (from Linear team label)
── Stage: Start Work ─────────────────────────
User clicks "Start Work" → confirms repo + branch
Deck spawns: claude --stream-json --resume <session>
cwd: /Users/kieran/.../monolith-django
stdin: /start-work VEC-24
→ Agent has MCP ✅ (Slack, Linear, Notion, GitHub)
→ Creates .work/vec-24-chat-rendering/plan.md
→ Deck reads plan.md → renders structured UI
── Stage: Hack ───────────────────────────────
User reviews plan, clicks "Start Hack"
Deck spawns: claude --stream-json --resume <session>
stdin: /hack (or /hack full auto)
→ Same session context, reads plan.md
→ Implements phases, commits per task
→ Deck streams progress via planning events
── Stage: Ship ───────────────────────────────
User clicks "Ship"
Deck spawns: claude --stream-json --resume <session>
stdin: /ship
→ Runs verification, pushes, opens PR
→ Deck extracts PR URL from output
── Stage: Review ──────────────────────────────
Auto-triggered after ship
stdin: /code-review
→ Parallel reviewer agents run
→ Deck reads .work/*/reviews/*.md → renders findings UI

Key Decisions

Transport: stream-json (not -p)
Full MCP access, real-time event streaming
State: .work/ on disk + session ID on task
--resume continues conversation context
Invocation: Skill slash commands as stdin
/start-work, /hack, /ship, /code-review
Non-interactive: CLAUDE_HIVE=1 env var
Skills skip confirmations, use best-judgment

What Changes from Current Architecture

Remove
  • Custom planning prompts (buildMcpPlanningPrompt)
  • Custom plan format (SECTION 1/SECTION 2)
  • askMcpPlanningAgent for planning
  • askEphemeralProcess for plan iteration
  • 3 custom planning skills in .claude/skills/
Keep
  • Poll bridge + triage (notification system)
  • Stream-json spawn infrastructure
  • Real-time event streaming to UI
  • Session resume capability
  • Process monitor + RAM tracking
